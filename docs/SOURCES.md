# 来源、快照与检查边界

本仓库从「果时志」项目提取 2026-11-05 的独立数据快照。六个输入 JSON 首次复制时保持原始字节，初始 SHA-256 见 `manifest.json` 及 Git 首次提交。

发布基线为 `records-full.json`，不是重新抓取网页后生成的实时数据库。没有携带原应用的全部研究输入、抓取缓存、页面全文、图片或开发流程，因此不宣称能从外部网站完整重现最初的人工研究。

## 追溯一条记录

1. 从 `id` 找到主记录，阅读 `kind`、`months`、`year`、`note` 和时间边界。
2. 阅读主来源 `sourceTitle`、`url`；需要时再查 `additionalSources`、`supportingUrl`。
3. `originSource` 可能只支持产地身份；品牌依据只支持其明确限定的品牌与年份，不能代替采收依据。
4. 品种与风味通过同 ID 查 `origin-profiles.json`，并核对该字段自己的来源。
5. 通过 `sources.json` 可反查同一 URL 在哪些文件、字段和记录中出现。

## 已做的离线检查

- 必填字段、唯一 ID、1–12 的月份与重复月份。
- 日期是否合法，主日期与记录月份、年度是否一致。
- 年度观察是否带年份，果期类型是否为已知值。
- 品种资料与别名引用是否指向存在的记录或来源。
- 已登记的现行修订是否保留在完整快照中。
- URL 格式、部分凭据形式、本地绝对路径与常见 token 模式。
- CSV、来源索引、统计、文件大小与哈希是否可重复生成。

这些检查不会联网重读外部网页，不判断作者身份、摘录授权、文本结论是否充分、同名地点是否混淆，也不代表完成全面隐私或密钥审计。已有来源中有政府、新闻、登记附件和行业页面，不应全部称为官方数据。

## 已知局限

- 原始水果与地区标签尚未完全归一化；月份集合、名称和产品卡片数不能混为同一统计口径。
- 果期受年份、品种、海拔、气候、栽培与留树保鲜等影响；资料参考不能保证某地当日可采、可买或开放。
- 出版日期可能只精确到月；保留该精度。
- 部分旧记录没有 `harvestWindow` 或 `checkedAt`，不为其补造分类或核验日期。
- 标题可能是编辑标注，PDF 链接可能指向汇编文件。使用时仍须对照具体章节和原始文字，不仅凭标题判断匹配。
- 外部链接可能失效或变更。贡献时可新增存档位置、页码或短证据说明；不要上传未经确认可分发的整篇文章或图片。

## 版本更新

修改现有数据时尽量保留 ID，记录旧口径与新依据。`snapshotDate` 表示这个独立发布基线的日期，未来发行新快照时维护者应在脚本中更新它，并写入更新记录。构建不会把当天日期冒充各条数据的重新核验日期。
